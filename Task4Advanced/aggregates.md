# Агрегаты и инварианты

Агрегат задаёт границу строгой транзакционной согласованности. Между агрегатами и bounded contexts действует
eventual consistency; распределённые транзакции не используются. Внешние идентификаторы хранятся как ссылки,
а не как копии чужих моделей.

| Контекст               | Корень агрегата / ключ              | Состав и граница                                                              | Ключевые инварианты                                                                                                                                                                      |
|------------------------|-------------------------------------|-------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Управление пациентами  | `Patient / patientId`               | Демография, контакты, региональные external IDs, согласия                     | `patientId` неизменяем; внешний ID уникален в паре `(issuer, region)`; согласие имеет область, срок и версию; отзыв согласия не удаляет юридически обязательную историю                  |
| Расписание и приём     | `Appointment / appointmentId`       | Выбранный слот, пациент, специалист, услуга, статус визита                    | Один слот нельзя подтвердить двум записям; переходы статуса допустимы только по state machine; завершить можно только начатый визит                                                      |
| Расписание и приём     | `Schedule / scheduleId`             | Доступные интервалы одного специалиста/ресурса на ограниченный период         | Слоты не пересекаются; недоступный специалист или ресурс не может иметь открытый слот                                                                                                    |
| Клиническая практика   | `ClinicalEncounter / encounterId`   | Эпизод, назначения, заключения и авторство                                    | Изменения только авторизованным медработником; подписанная запись не перезаписывается, исправление добавляется версией; заключение ИИ не становится клиническим без подтверждения врачом |
| Диагностика            | `DiagnosticStudy / studyId`         | Назначение, тип, состояние выполнения, ссылки на результат и изображения      | Исследование связано с одним назначением и пациентом; завершение требует результата или документированной причины; бинарные данные не помещаются в событие                               |
| Оркестрация ИИ         | `AIAnalysis / analysisId`           | Ссылка на исследование, версия модели, параметры, результат и статус проверки | Версия модели фиксируется до запуска; один `requestId` обрабатывается один раз; результат хранит provenance; отозванная модель не принимает новые задания                                |
| Жизненный цикл моделей | `ModelVersion / modelVersionId`     | Артефакт, метрики валидации, область применения и статус                      | В production допускается только утверждённая версия; артефакт и набор валидации имеют checksum; отзыв необратим, повторный выпуск создаёт новую версию                                   |
| Биллинг                | `Invoice / invoiceId`               | Строки начислений, сумма, валюта, оплаты и состояние долга                    | Сумма равна сумме строк с правилами округления; валюта одна; оплаченная сумма не выше остатка; выставленный счёт исправляется корректировкой, а не перезаписью                           |
| Платежи                | `Payment / paymentId`               | Intent, попытки провайдера, сумма, проводки и возвраты                        | `idempotencyKey` уникален; сумма и валюта фиксируются при подтверждении; сумма возвратов не выше успешной оплаты; переход состояния монотонен                                            |
| Кредитование           | `CreditApplication / applicationId` | Запрошенные условия, снимок входных данных, решение                           | Одно финальное решение; решение содержит версию правил/модели и основания; одобрение имеет срок действия                                                                                 |
| Кредитование           | `LoanAgreement / loanAgreementId`   | Условия, график, учтённые платежи, просрочки                                  | Договор создаётся только из действующего одобрения; сумма графика согласуется с условиями; платёж учитывается идемпотентно; история графика версионируется                               |
| Персонал               | `Employee / employeeId`             | Трудовой статус, подразделение, роли и период занятости                       | Интервалы занятости не пересекаются; уволенный сотрудник не получает новые активные роли; чувствительные HR-атрибуты не публикуются                                                      |
| Ресурсы и инвентарь    | `Resource / resourceId`             | Оборудование/кабинет, местоположение, состояние и обслуживание                | Ресурс на обслуживании недоступен для записи; серийный номер уникален в организации; смена региона требует контролируемой передачи                                                       |
| Подключение партнёров  | `PartnerConnection / partnerId`     | Партнёр, разрешённые операции, версия контракта, credentials metadata         | Только активный договор разрешает обмен; входящее сообщение проходит аутентификацию, schema validation и дедупликацию; секреты не входят в агрегат и события                             |

## Согласованность и конкуренция

- Команда адресует один агрегат. Транзакция изменяет его состояние и добавляет событие в outbox атомарно.
- Оптимистическая блокировка по `aggregateVersion` предотвращает потерю конкурентных изменений.
- Межконтекстный process manager хранит только correlation IDs и собственное состояние саги; он не становится
  владельцем доменных данных.
- Компенсация выражается новой командой и новым фактом (`PaymentRefunded`, `AppointmentCancelled`), а не удалением
  ранее опубликованного события.
- Потребители дедуплицируют сообщения по `eventId`, а бизнес-операции — по `idempotencyKey`/business key.
